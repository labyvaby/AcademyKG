# БАГ (бэк): оплата со 100% скидкой не закрывает приём (2026-06-08)

> **Приоритет: ВЫСОКИЙ.** Кассиры не могут провести приём со 100% скидкой —
> он остаётся в статусе «Ожидаем» (`scheduled`), хотя долг = 0.

## Симптом

Кассир ставит скидку 100% и подтверждает оплату. Запрос проходит (HTTP 200),
долг обнуляется, но приём **остаётся `scheduled`** — выглядит как неоплаченный.
«Оплата со скидкой 100% не проходит».

## Воспроизведение (проверено вживую, суперадмин-токен)

Приём `6c81ca78-…`, `totalAmount=1000`, `scheduled`.

### 1. Как шлёт фронт при 100% скидке (без `status`)
```
PATCH /api/v1/appointments/6c81ca78-.../
{ "paidCash":0,"paidCard":0,"paidBalance":0,"paidBonuses":0,"discount":1000 }
→ HTTP 200
→ discount=1000.00, debt=0.00, status="scheduled"   ← статус НЕ изменился
```

### 2. Пытаемся форсить статус явно
```
PATCH … { "status":"paid", "discount":1000, "paidCash":0, ... }
→ HTTP 200, но в ответе status="scheduled"   ← бэк ПЕРЕЗАПИСАЛ статус обратно
```

**Вывод:** бэкенд выводит статус из суммы фактической оплаты
(`paidCash+paidCard+paidBalance+paidBonuses`) и игнорирует скидку. При нулевой
оплате (даже когда `debt=0` за счёт скидки) статус принудительно остаётся
`scheduled`. Фронт переопределить не может — присланный `status:"paid"` затирается.

## Что нужно

Статус приёма должен выводиться из **долга**, а не только из суммы платежа:
когда `debt == 0` (вне зависимости от того, закрыт он оплатой или скидкой),
приём должен становиться `paid` (или закрытым). Т.е. учитывать `discount`
в расчёте «оплачено полностью».

## Связанный баг: статус `free` отсутствует в enum

Кнопка «Бесплатно» (фронт) шлёт `status:"free"`:
```
PATCH … { "status":"free", "discount":1000, ... }
→ HTTP 400 {"code":"invalid_choice","detail":"Значения free нет среди допустимых вариантов.","attr":"status"}
```
Валидный `StatusFceEnum`: `scheduled, arrived, in_progress, completed, paid,
partially_paid, cancelled, no_show, not_came` — **нет** `free`/`discounted`.

→ Кнопка «Бесплатно» сейчас тоже не работает (400).

### Вопрос к бэку
Как помечать **полностью бесплатный / 100%-скидочный** приём — отдельным
статусом (`free`/`discounted`, добавить в enum) или общим `paid` при `debt==0`?
Фронт уже умеет отображать и «Бесплатно», и «Со скидкой» — если добавите статусы
в enum, фронт подхватит. Если выбираете `paid` при `debt==0` — тогда оба бага
(этот и `free`-кнопка) закрываются одной серверной логикой, а фронт мы поправим
(перестанем слать `status:"free"`).
