# Запрос к бэкенду — отчёт «Занятия за день» (daily-lessons)

Контекст: заказчику нужен дневной PDF-отчёт детализации занятий (фото-образцы
от 2026-06-15, дни 08/09/11/12.06.2026). Это **отдельный** отчёт, не «Сводка дня».
Фронт уже строит PDF под контракт ниже; до реализации ендпоинта кнопка отдаёт
ошибку «ендпоинт не готов». Принятые с заказчиком решения — в конце документа.

## Что на образце

Одна страница на один день. Две таблицы:

### 1. «Занятия» (индивидуальные приёмы) — колонки `Занятия | Кол | сумм | Итого`
- Группировка **по услуге** (`SellableItem`), услуга = «категория» (СМК, С.И,
  Дефектолог, Логопед, Массаж Общ., Массаж общий взрослый, …). Набор категорий
  динамический — какие услуги были в этот день, такие и строки.
- Внутри категории:
  - **Синяя строка (агрегат по стандартной цене)**: все занятия категории,
    проведённые по стандартной цене услуги. Показывает `Кол` (число занятий),
    `сумм` (стандартная цена за занятие), `Итого` (Кол × сумм).
  - **Белые строки (исключения)**: каждое занятие по НЕстандартной цене
    (тех.персонал, скидка, особая ставка) — отдельной строкой с указанием
    специалиста и ребёнка. Пример: «СМК Алымбек А - (Эркин)» 1 / 600 / 600.
- Итоговая строка таблицы: сумма `Кол` и сумма `Итого` по всем категориям
  (на образце 12.06 — 78 / 71680).

### 2. «АФК» (абонементы групп) — колонки `АФК | Кол д | Сумма | Итого`
- Источник — `client-subscriptions` (абонементы), оформленные/оплаченные в этот день.
- Группировка по тарифу/периоду. Пример строк:
  - «11 чел. 1.06.2026 по 30.06.2026. абон.плата за Июнь» — 11 / 10000 / 110000
  - «6 чел. 8.06.2026 по 30.06.2026. 500 за 17 дней» — 6 / 8500 / 51000 (пропорция от середины месяца)
- `Кол д` = число человек (детей), `Сумма` = цена за человека, `Итого` = Кол × Сумма.
- Итог: сумма человек и сумма Итого (на образце 08.06 — 17 / 161000).
- Если в день абонементов не оформляли — пустой блок с итогом 0 (образец 12.06).

## Запрос

```
GET /api/v1/reports/daily-lessons/?branch={uuid}&date={YYYY-MM-DD}
```

- `branch` — **обязателен** (UUID), как в `daily-summary`.
- `date` — **обязателен** (YYYY-MM-DD), один день.
- Права: `reports.read` (superadmin/accountant) — консистентно с `daily-summary`
  и `specialist-payslip`.
- Конверт ответа — как у остальных reports: `{ "data": {...}, "meta": {...} }`.

## Ответ (контракт, под который написан фронт)

```jsonc
{
  "date": "2026-06-12",
  "branch": { "id": "uuid", "name": "...", "brandName": "Академия KG" },

  "lessons": {
    "categories": [
      {
        "name": "СМК",                 // имя услуги/категории (для синей строки)
        "order": 0,                    // порядок вывода (см. вопрос Q3)
        "standard": {                  // синий агрегат; если по стандартной цене занятий нет — count 0
          "count": 21,
          "unitPrice": "1000.00",
          "total": "21000.00"
        },
        "exceptions": [                // белые строки — занятия по особой цене
          {
            "specialistName": "Алымбек А",   // performer
            "patientName": "Эркин",          // ребёнок
            "note": "тех.персонал",          // повод особой цены или "" (может быть пустым)
            "count": 1,
            "unitPrice": "600.00",
            "total": "600.00"
          }
        ],
        "subtotal": { "count": 23, "total": "22100.00" }  // standard + exceptions по категории
      }
    ],
    "totals": { "count": 78, "total": "71680.00" }   // по всем категориям
  },

  "afk": {
    "rows": [
      {
        "label": "11 чел. 1.06.2026 по 30.06.2026. абон.плата за Июнь", // готовая подпись

        "total": "110000.00"
      }
    ],
    "totals": { "count": 17, "total": "161000.00" }

Денежные поля — строки-decimal (как везде в reports). Фронт парсит сам.

## Решения, согласованные с заказчиком (2026-06-15)

1. **Категория занятия = услуга приёма** (`SellableItem`). Не роль специалиста.
   «Массаж Общ.» (800) и «Массаж общий взрослый» (1500) — разные услуги/строки.
2. **Синяя vs белая строка** — подтверждено: синяя = агрегат занятий по
   стандартной цене категории; белая = отдельное занятие по особой цене с
   именем ребёнка и специалиста.
3. **В отчёт входят только ОПЛАЧЕННЫЕ занятия** (фактический платёж за этот день
   > 0). Неоплаченные/неявки/только запланированные — не учитываются.
4. **Один день = один файл** (date обязателен, диапазона нет).

## Открытые вопросы к бэку (просьба подтвердить/решить)

- **Q1. Что такое «стандартная цена» услуги для разделения синяя/белая?**
  Предлагаемое определение: стандартная = настроенная цена `SellableItem`
  (`displayPrice`). Занятие по этой цене → в синий агрегат; по любой другой
  (скидка, тех.ставка) → отдельная белая строка. Если в системе цена не
  фиксирована per-service, нужен иной критерий (напр. модальная цена дня) —
  подскажите.
- **Q2. Что считать «оплаченным занятием» для охвата?**
  Предлагаем: услуга приёма (`AppointmentService`), по которой за этот день
  прошёл платёж (`paid_* > 0`) ИЛИ покрыта абонементом в этот день. Уточните,
  входят ли занятия, покрытые абонементом, в «Занятия» или только в «АФК».
- **Q3. Порядок и состав категорий.** Брать ли фиксированный порядок
  (СМК, С.И, Дефектолог, Логопед, Массаж…) из настройки услуг, или сортировать
  по имени / по обороту? Пока фронт выводит в порядке `order` из ответа.
- **Q4. Формат `note` и подписи белой строки.** Откуда берётся «тех.персонал» —
  это флаг роли исполнителя или коммент? Если структурно — отдайте признак,
  иначе строкой в `note`.
- **Q5. АФК: какие абонементы попадают в день.** Предлагаем: `client-subscriptions`
  с датой оформления/оплаты (`createdAt` / `createdFromPayment`) = выбранный день.
  В списке `client-subscriptions` сейчас НЕТ фильтра по дате — для этого отчёта
  он не нужен (агрегируете на бэке), но подтвердите критерий «попал в день».
  `Сумма` за человека — это `paidAmount` (фактически оплачено, с учётом
  пропорции «500 за 17 дней») или `monthlyPrice`? На образце видно пропорцию →
  похоже на фактически начисленное за оставшиеся дни.
