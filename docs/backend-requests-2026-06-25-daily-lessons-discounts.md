# «Занятия за день»: скидочные занятия не попадают в таблицу

[ПРИОРИТЕТ: ВЫСОКИЙ] · дата: 2026-06-25 · эндпоинт `GET /api/v1/reports/daily-lessons/`

## Симптом (заказчик)

В таблице «Занятия» дневного отчёта **не фиксируются скидочные занятия** —
по услугам дефектология, логопед-дефектолог, массаж общий детский и др. Занятия,
проведённые со скидкой/по особой цене, должны идти **белой строкой-исключением**
(`category.exceptions[]`), но не появляются.

## Фронт проверен — он корректен

Фронт рендерит **все** `categories[].exceptions[]` как белые строки
(`services/dailyLessons.ts` → `utility/dailyLessonsPdf.ts`, без фильтра). Значит
скидочные занятия **не приходят в ответе**. Корень — на бэке.

## ПОДТВЕРЖДЕНО на живых данных (Главный филиал, 2026-06-22, суперадмин GET)

В этот день в филиале было **3 скидочных приёма** (частичная скидка, оплачены):
```
СМК           total=1000  discount=400  paid=600  status=paid  perf=Аскаров Тамирлан
СМК           total=1000  discount=400  paid=600  status=paid  perf=Байматов Нурлан
Дефектология  total=1000  discount=400  paid=600  status=paid  perf=Койбагарова Гульзат
```
Ответ `GET /reports/daily-lessons/?branch=<Главный>&date=2026-06-22`:
```
CAT "Дефектология" std{count:12, unitPrice:1000, total:12000} exceptions:[]
CAT "Логопед"      std{count:5,  unitPrice:800,  total:4000}  exceptions:[]
CAT "Логопед час"  std{count:3,  unitPrice:1000, total:3000}  exceptions:[]
CAT "СИ"           std{count:11, unitPrice:800,  total:8800}  exceptions:[]
CAT "СМК"          std{count:28, unitPrice:1000, total:28000} exceptions:[]
lessons.totals: { count:59, total:55800 }
```
**Exceptions пусты во ВСЕХ категориях.** Скидочные занятия попали в **синий
`standard`** и посчитаны по **номинальной** цене: СМК 28×1000 (2 скидочных учтены
как 1000, а не 600), Дефектология 12×1000 (1 скидочное как 1000). Итог `total=55800`
**завышен** на 3×400 = 1200 (фактически оплачено 54600).

## Причина (подтверждена) — классификация по номинальной цене, а не по фактической

Бэк делит «стандарт vs исключение» по номинальной цене `SellableItem` (priceSom).
Скидочное занятие имеет **ту же** номинальную цену → уходит в синий агрегат,
отдельной белой строки нет, а его выручка считается по номиналу (1000), а не по
факту (600).

**Нужно:** «исключение» определять по **фактической цене занятия за вычетом
скидки** (effective = `total_amount − discount` по услуге/приёму), а не по
номиналу `SellableItem`. Если effective ≠ стандартной цены услуги → белая строка:
`note` = причина (скидка/тех.персонал), `unitPrice`/`total` = фактическая.
Заодно `standard.total` и `lessons.totals.total` должны считаться по фактической
оплате, иначе выручка отчёта завышена.

## Вторичная причина — фильтр «только оплаченные (paid_*>0)» отсекает 100%-скидку

Decision #3: в отчёт входят только занятия с `paid_*>0`. Занятие со **100%
скидкой** имеет `paid_* = 0` (вся сумма ушла в `discount`, `debt=0`) — см.
связанный баг 100%-скидки (статус `paid`, `paid*=0`). Такое занятие **проведено и
закрыто скидкой**, но фильтр его выкидывает.

**Нужно решение заказчика/бэка:** скидочные (в т.ч. 100%) занятия должны
**входить** в отчёт. Предлагаю критерий охвата: занятие **закрыто** за этот день —
`paid_* > 0` **ИЛИ** `discount > 0` (debt=0 за счёт скидки) **ИЛИ** покрыто
абонементом. Тогда `unitPrice`/`total` белой строки = фактически начисленное за
вычетом скидки (может быть 0 при 100% — подтвердите, показывать ли 0 или номинал).

## Открытые вопросы

1. Подтвердите фикс: «исключение» = занятие с effective-ценой
   (`total_amount − discount`) ≠ стандартной цене услуги; `standard`/`totals`
   считать по фактической оплате, а не по номиналу.
2. Для белой строки скидочного занятия `unitPrice` = фактически оплачено (со
   скидкой). На образце исключения показывают фактическую (600 при стандартной 1000).
   Подтверждаете?
3. 100%-скидка (paid=0, debt=0 за счёт скидки): включать в отчёт белой строкой
   (с суммой 0 или номиналом?), или такие в «Занятия» не нужны?
