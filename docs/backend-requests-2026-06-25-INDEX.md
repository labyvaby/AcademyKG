# Бэклог запросов к бэкенду — 2026-06-25

Единая точка входа по тикетам этой сессии. Детали — в отдельных доках по ссылкам.
Часть подтверждена живой проверкой на боевой базе (`academy.operator.kg`, только GET).

## 🔴 Высокий приоритет

### 1. Расчётный лист: реальное время приёмов вместо сетки 08–18
[`backend-requests-2026-06-25-payslip-slots.md`](./backend-requests-2026-06-25-payslip-slots.md)
`specialist-payslip` отдаёт фиксированную сетку 11 часовых слотов 08:00–18:00.
Приёмы вне 08–18 **выпадают**, off-grid времена округляются, коллизии в одном часе
сливаются. **Подтверждено вживую:** Манас работает до 23:30 → у Собирова Сардарбека
в листе 103 из 140 приёмов (**−26%**). Нужно: `slots[]` = строка на каждый фактический
приём со своим `HH:mm`.

### 2. «Занятия за день»: скидочные занятия не попадают в таблицу
[`backend-requests-2026-06-25-daily-lessons-discounts.md`](./backend-requests-2026-06-25-daily-lessons-discounts.md)
Бэк делит «синяя/белая» по номинальной цене `SellableItem`, поэтому скидочные уходят
в синий агрегат по номиналу, белой строки нет, **выручка завышена**. **Подтверждено
вживую** (Главный 22.06: 3 скидочных, `exceptions:[]`, total 55800 вместо 54600).
Нужно: классифицировать «исключение» по фактической цене (`total_amount − discount`),
`standard`/`totals` считать по факту.

### 3. Оплата за период: вся выручка в день оплаты
[`backend-requests-2026-06-25-period-payment-revenue-day.md`](./backend-requests-2026-06-25-period-payment-revenue-day.md)
Сейчас оплата за срок дробится по приёмам (каждый на своей дате) → выручка
размазывается по дням. Нужно признавать всю сумму в день оплаты, приёмы покрыты
(без долга). Заработок специалиста при этом НЕ переносить (остаётся на дне сессии).
Фронт ждёт контракт (сигнал/механизм даты).

### 4. Ребёнок сотрудника: авто-удержание с родителя-специалиста
[`backend-requests-2026-06-25-employee-child-deduction.md`](./backend-requests-2026-06-25-employee-child-deduction.md)
При оплате приёма ребёнка сотрудника — авто-`deduction` на `employeeParent` на сумму
`цена − скидка` (скидки может не быть → полная цена), ребёнок платит 0. Данные есть
(`employeeParent`, `employeeChildDiscountPercent`). На бэке ради идемпотентности
(«Перепровести оплату» не должно задваивать).

## 🟡 Средний приоритет

### 5. Отчёты: `appointmentsCount` считает отменённые приёмы
[`backend-reports-count-mismatch.md`](./backend-reports-count-mismatch.md)
Корень «256 vs 255»: `financial-monthly.appointmentsCount` включает `cancelled`
(256), а реально проведённых 255 (= `aggregated`). **Подтверждено вживую** (Главный
256/255, Манас 1862/1860 = по числу отменённых). Нужно: исключить `cancelled`
(и возможно `no_show`/`not_came`) из счётчика. Фронт уже сведён к одному полю.
