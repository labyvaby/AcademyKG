# QA CRUD Regression Checklist

Этот чеклист покрывает исправления после CRUD-рефакторинга и нужен для ручной регрессии перед выкладкой.

## Подготовка

1. Запустить приложение и авторизоваться под ролью с полным доступом.
2. Подготовить тестовые данные:
   - минимум 1 клиент с балансом и бонусами
   - минимум 1 активный специалист
   - минимум 1 услуга
   - минимум 1 товар
   - минимум 1 категория расхода, включая "Аванс" и "Заработная плата"
3. Проверить, что backend доступен и изменения сохраняются не только в UI, но и после перезагрузки страницы.

## Home / Payment Flow

### Базовая оплата

1. Открыть приём на [home](/c:/Users/laby/Desktop/academyKG/src/pages/home/index.tsx).
2. Нажать "Принять оплату".
3. Ввести наличные или безнал.
4. Сохранить.

Ожидание:
- оплата сохраняется
- приём остаётся в корректном статусе
- после перезагрузки данные не теряются

### Баланс и бонусы

1. Выбрать клиента с ненулевым балансом или бонусами.
2. В оплате списать часть суммы с баланса.
3. Сохранить.
4. Открыть карточку клиента и проверить баланс.
5. Повторить сценарий с бонусами.

Ожидание:
- в приёме сохраняются `paidBalance` и `paidBonuses`
- баланс клиента уменьшается на ту же сумму
- при повторном открытии суммы совпадают

### Изменение уже сохранённой оплаты

1. Открыть уже оплаченный приём.
2. Изменить распределение между наличными, балансом и бонусами.
3. Сохранить.

Ожидание:
- старые суммы корректно замещаются новыми
- клиентский баланс пересчитывается без двойного списания

### Негативный сценарий rollback

1. Смоделировать ошибку backend на одном из шагов оплаты.
2. Сохранить оплату.

Ожидание:
- если второй шаг падает, приём не должен остаться в частично сохранённом состоянии
- баланс и платёжные поля должны быть консистентны
- пользователь видит ошибку

## Patient Search

### Create visit

1. Открыть [patient-search](/c:/Users/laby/Desktop/academyKG/src/pages/patient-search/index.tsx).
2. Выбрать клиента.
3. Открыть форму создания визита.
4. Указать дату, врача и услугу.
5. Сохранить.

Ожидание:
- приём создаётся через API
- запись появляется в истории клиента
- после обновления страницы запись остаётся

### Update visit

1. В истории клиента открыть редактирование приёма.
2. Изменить дату, врача или услугу.
3. Сохранить.

Ожидание:
- редактируется существующий приём, а не создаётся новый
- история клиента обновляется

### Edge cases

1. Ввести неоднозначное имя врача.
2. Ввести неоднозначное название услуги.

Ожидание:
- форма не сохраняет приём вслепую
- пользователь получает понятную ошибку
