# Запрос бэкенду: месячный оклад в зарплатных правилах (2026-07-06)

## Что нужно

Заказчик хочет задавать сотруднику **фиксированный оклад за месяц** — рядом с уже существующими ставками «за день/час» и «за приём».

Фронт уже отправляет новое поле в `PATCH /api/v1/employees/{id}/`:

```jsonc
{
  "salaryRules": {
    "fixedSalary": {
      "enabled": true,
      "monthlyRate": "30000",      // ← НОВОЕ поле, строка — как dayHourlyRate/appointmentRate
      "dayHourlyRate": "0",
      "appointmentRate": "0"
    },
    "dynamicRules": [ /* без изменений */ ]
  }
}
```

И ожидает его обратно в `GET /api/v1/employees/{id}/` → `salaryRules.fixedSalary.monthlyRate`.

## Что нужно от бэка

1. **Персист**: принимать и возвращать `salaryRules.fixedSalary.monthlyRate`.
   Если сериализатор `salaryRules` строгий (не JSON-as-is) — добавить поле; иначе ничего делать не надо.
2. **Расчёты**: включать оклад в начисления сотрудника:
   - `GET /api/v1/reports/payroll-monthly/` — в `PayrollRow.fixedSum` и `grossEarnings` (и, соответственно, `netSalary`);
   - `GET /api/v1/reports/specialist-payslip/` — в `summary.grossEarnings` (структура ответа не меняется).

Фронт расчёты не дублирует — суммы берутся готовыми с бэка (это уже принятое правило по payslip).

## Открытые вопросы (нужно решение, фронт НЕ закладывал дефолтов)

1. **Строгость сериализатора**: не отвергает ли текущий `PATCH /employees/{id}/` неизвестное поле `monthlyRate` с 400? Если да — сохранение сотрудника сломано до бэк-фикса, просим приоритезировать.
2. **Пропорция за полупериод**: как оклад входит в `specialist-payslip` при `periodHalf=first/second` — 50/50, по календарным дням, или только в полный месяц?
3. **Неполный месяц**: сотрудник принят/уволен в середине месяца — оклад целиком или пропорционально?
4. **Взаимодействие со ставками**: оклад суммируется с `dayHourlyRate`/`appointmentRate`/динамическими правилами или взаимоисключается? Фронт-UI позволяет заполнить всё сразу — предполагаем суммирование, но это догадка.
5. **Куда в отчёте**: оклад попадает в существующий `fixedSum` или нужно отдельное поле (например, `monthlySalarySum`), чтобы в UI различать «оклад» и «фикс за приёмы/часы»?

## Статус фронта

- Поле «Оклад (месяц)» добавлено в настройки зарплаты сотрудника (drawer редактирования).
- Отправляется/читается как `salaryRules.fixedSalary.monthlyRate` (строка, camelCase — симметрично соседним полям).
- Отчёты («Зарплаты», расчётный лист) автоматически покажут оклад, как только бэк включит его в `fixedSum`/`grossEarnings`.
