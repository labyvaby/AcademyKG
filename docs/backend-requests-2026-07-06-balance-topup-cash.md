# Пополнение баланса клиента не отражается ни в одном отчёте (живые деньги выпадают из кассы)

[РЕШЕНО БЭКОМ 2026-07-06] · контекст: запрос заказчика «оплата балансом должна отображаться в отчётах»

## Ответ бэка (2026-07-06) и проверка вживую

Реализована модель авансовых платежей: пополнение = приход кассы (cash/card,
день транзакции); оплата балансом = выручка без движения денег (balance_sum);
virtual-транзакции (paymentMethod=null, т.е. списания при оплате) кассой
игнорируются; возврат — минус из соответствующей кассы.

Проверено вживую на тестовых данных этого тикета (Тестовый филиал, 06.07):
cashbox `net.cashSum=2000` ✅, financial-monthly `days[].cashSum=2000` ✅,
daily-summary `income.cash=2000`, `currentDayCashNet=2000` ✅, `servicesSum`
не задвоился ✅.

Открытый вопрос 2 закрыт фронтом: `income.total` (= cash+cashless+balance+bonuses)
задваивает балансовые деньги (день пополнения через cash + день оплаты через
balance) → кассовые строки «Сводки дня» переведены с `income.total` на
`income.cash + income.cashless` (см. `services/dailySummary.ts`, 2026-07-06).

## Что нужно

1. Пополнение баланса (`client-balance-transactions`, положительный `amount`
   с `paymentMethod`) должно попадать в кассовые агрегаты по способу оплаты:
   `cashbox/summary` (как минимум `net.cashSum`/`net.cardSum` — заказчик сверяет
   физическую кассу) и `daily-summary` (кассовые строки/`cashPosition`).
2. При этом НЕ задваивать: если пополнение признаётся приходом кассы в день
   пополнения, то списание баланса при оплате приёма — это не движение денег
   (выручка да, касса нет). Скажите, какую модель выберете — фронт подстроится.

## Открытые вопросы (нужно решение, фронт дефолтов не закладывал)

1. **Модель признания**: пополнение = приход кассы (день пополнения), списание
   баланса = выручка без движения денег (день оплаты)? Или иная схема?
2. **`daily-summary.income.total` включает `balance`** — для строк «наличка»
   (`total − операц.расходы`, модель заказчика 2026-06-15) это даёт кассу,
   за которой не стоят живые деньги дня, а пополнения в ней отсутствуют.
   Как правильно: отдельное поле «денежный приход» (cash+cashless+пополнения)?
3. **Возврат/сгорание баланса** — где отражается отрицательная транзакция
   без `paymentMethod` (списание при оплате)? Ожидаем: нигде (не движение денег).
4. **История**: пополнения прошлых месяцев в отчёты задним числом не попадут?
   Нужна ли миграция/пересчёт — решение за вами, фронт не пересчитывает.
