# Валюта филиала (branch.currency)

**Дата:** 2026-07-08
**Контекст:** для филиалов в другой стране (первый кейс — Узбекистан, сум) нужно
показывать суммы в валюте филиала. Пересчёт по курсу НЕ нужен: цены и платежи
задаются и хранятся сразу в валюте того филиала, где совершена операция.
Фронту нужна только подпись/формат валюты.

## Запрос

Добавить в модель филиала поле **`currency`** — код валюты (ISO 4217):

```
Branch {
  ...
  currency: string   // "KGS" | "UZS" | "KZT" | ...  (по умолчанию "KGS")
}
```

- Отдавать в `GET /api/v1/branches/` и в `employee.primaryBranch` (фронт читает
  валюту оттуда для не-суперадминов — тот же путь, что brandName/logoUrl).
- Редактируемое в настройках филиала (там же, где название/лого).
- Default для существующих филиалов — `"KGS"` (сом), чтобы Кыргызстан не менялся.

## Что уже сделано на фронте (работает после появления поля)

- `utility/currency.ts` — реестр валют (KGS/UZS/KZT/RUB/USD), `formatMoney`,
  `getCurrencySuffix`. Fallback на KGS, если `currency` не пришёл.
- `BranchOption.currency`, `branch-context`, `useEffectiveBranch` — прокидывают
  `currency` из ответа бэка.
- Хук `useBranchCurrency()` — валюта эффективного филиала + хелперы формата.
- Применено: `PaymentInfoBlock` (чек оплаты). Остальные места (PDF-отчёты,
  drawer'ы расходов, товары, групповые приёмы) переводятся на утилиту поэтапно.

## Открытые вопросы

1. Формат хранения кода — строго ISO 4217 (`"UZS"`) или свой enum? Фронт ждёт ISO.
2. Режим «Все филиалы» со смешанными валютами — суммирование сейчас НЕ решается
   (по договорённости пока не важно). Как договоримся — либо не суммировать, либо
   группировать итоги по валюте.
3. Нужна ли валюта в других сущностях (услуги/товары/платежи) отдельно, или она
   всегда наследуется от филиала операции? Фронт исходит из «валюта = у филиала».
