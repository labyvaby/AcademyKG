# Сотрудник не может сменить пароль — не знает текущий — 2026-10-27

## Симптом

Клиент (Бек) пишет: «Не можем пароль поменять, не знаем текущий пароль. Функции „забыл пароль“ нет».
Он открывает «Профиль → Пароль → Смена пароля», а форма требует «Текущий пароль *».

## Причина

- Сотрудники входят **по SMS** (`POST /auth/login/` → `POST /auth/verify/`, `purpose: "login"`).
- Сотрудник создаётся через `POST /api/v1/employees/` с `userPhoneNumber`, **без пароля**.
  Значит у user либо unusable password, либо случайный пароль, который никто не знает.
- `POST /api/v1/auth/change-password/` требует `oldPassword` → для таких пользователей смена
  пароля невозможна в принципе.
- «Забыли пароль?» есть только на экране входа, на вкладке Email, и работает только по email.

Что существует на проде (проверено 2026-10-27 GET-запросом без токена):

| Endpoint | Ответ | Вывод |
|---|---|---|
| `/api/v1/auth/change-password/` | 401 | есть, требует `oldPassword` |
| `/api/v1/auth/reset-password/request/` | 405 | есть (POST) |
| `/api/v1/auth/reset-password/confirm/` | 405 | есть (POST) |
| `/api/v1/auth/set-password/`, `/auth/reset-password/sms/` | 404 | нет |
| `/api/v1/employees/{id}/set-password/`, `/users/{id}/set-password/` | 404 | нет |
| `/api/v1/users/admin-create/` (есть в коде фронта) | 404 | нет — во фронте мёртвый код |

## Что уже сделано на фронте

В форме «Смена пароля» добавлена кнопка **«Не знаю текущий пароль»**. Она вызывает
`POST /auth/reset-password/request/ { email, redirectUrl: "<origin>/reset-password" }`
с email из профиля. Если email в профиле нет, просим добавить его или обратиться к админу.

Это временный обход: он работает только при наличии email и только если письмо реально уходит.

## Вопросы (нужен ответ, чтобы понять, работает ли обход)

1. Отправляет ли `reset-password/request` письмо пользователю **без usable password**?
   Стандартный Django `PasswordResetForm.get_users()` таких молча отфильтровывает: ответ 200,
   а письмо не уходит. Если у вас похожая логика, просим её снять для этого endpoint.
2. Настроен ли SMTP на проде, доходят ли письма? Какой срок жизни ссылки?
3. Меняет ли `PATCH /api/v1/users/me/ { email }` тот же email, по которому ищет reset?

## Что просим

1. **Смена пароля через SMS-код вместо старого пароля** (основное, закрывает кейс без email):
   - `POST /api/v1/auth/change-password/otp/`: отправить SMS-код на телефон текущего пользователя;
   - `POST /api/v1/auth/change-password/` принимает **либо** `oldPassword`, **либо**
     `smsCode` (+ `newPassword`, `passwordConfirm`). После успеха, как сейчас,
     инвалидировать refresh-токены.
2. **Флаг `hasPassword: boolean` в `GET /api/v1/users/me/`**: фронт для пользователей без пароля
   покажет «Установить пароль» без поля «Текущий пароль».
3. **Сброс пароля сотрудника администратором** (запасной вариант):
   `POST /api/v1/employees/{id}/set-password/ { newPassword }`, право на это —
   permission (например `users.update`), а не жёсткая проверка роли.

Если п.1 сложно, минимальный вариант: разрешить `change-password` **без** `oldPassword`,
когда у пользователя `has_usable_password() == False`.
